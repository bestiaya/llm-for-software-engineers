# 11｜位置与多头：知道顺序，也保留多种读取方式

上一章已能算一个注意力头。本章解决两个缺口：相同 token 换个顺序，输入里有什么变化？多个头的结果怎样回到同一条数据流？先读[单头注意力](10-attention.md)，本章只增加位置与接口。

## 1. 因果遮罩和位置，分别解决什么

这节要分清“允许读谁”和“知道谁在第几位”，不要把两者当成同一个功能。

用上一章预切好的教学标签“服务 / 超时 / 重试”。如果只做不带遮罩、不带位置的注意力，把后三项中的两项交换，查询面对的仍是同一组键值，只是它们的排列变了。加权和对键值的同步重排不变。输出会随查询的重排而重排，却不会凭空多出绝对位置。

例如查询给两个键的分数是 `[0, ln(3)]`，其中 `ln` 读“自然对数”。softmax 权重为 `[1/4,3/4]`；值为 `[2,4]`，结果是 `1/4×2+3/4×4=3.5`。同时把分数和值交换，结果变成 `3/4×4+1/4×2=3.5`。这里是人为设定的一维小例，说明求和的性质，不是训练结果。

因果遮罩则让第0位只读第0位，第1位读前两位。它打破了“任意交换行而计算完全等价”的条件，因此**不能说带因果遮罩的网络完全没有任何顺序线索**：可见集合本身有先后差异。但它没有显式给出“现在是第17位”或“两次出现相隔多少位”的数值。本课在遮罩之外加入位置向量。

| 机制 | 给模型什么 | 没有保证什么 |
|---|---|---|
| 因果遮罩 | 当前行不能访问未来 | 不提供一张绝对位置编号表 |
| 位置向量 | 输入中可区别不同位置 | 不阻止未来信息泄漏 |
| 两者同时使用 | 有位置的合法前缀 | 不保证模型已经学会语法 |

> 因果性的检验仍然是：改未来 token，过去位置的输出应保持不变。给每行加位置向量并不能代替这项检验。

## 2. 把位置加在哪里

这节跟踪一次逐元素相加，理解位置维度与特征维度不同。

设“服务”的 token 向量为 `[1,0]`，第0位位置向量为 `[0.1,0.2]`，第1位为 `[0.3,-0.1]`。那么同一个 token 在两个位置进入网络时分别是：

```text
第0位：[1,0]+[0.1,0.2]=[1.1,0.2]
第1位：[1,0]+[0.3,-0.1]=[1.3,-0.1]
```

写成 `x_t = E[id_t] + P[t]`。`t` 读“位置t”，从0开始；`id_t` 是该位置的 token 编号；`E` 是按 token 编号查的向量表；`P` 是按位置查的向量表；`x_t` 是相加后的输入向量。两个表都由训练更新，不是先写好“第1维代表语义，第2维代表位置”。

完整实验的输入张量是 `[B,T,32]`：`B` 读“批大小”，是同时处理的序列数；`T` 是每条序列的位置数；32是每个位置的特征数。位置表形状是 `[64,32]`，取前T行后，给批中的每条序列使用同一组位置编号。位置不是额外的第33维，也不是把 token ID 与位置整数相加。

本课使用**学习式绝对位置**，最多64个位置。训练过长度64不表示能直接访问位置100；换成长上下文属于另一个设计与验证问题。原始 Transformer 论文还讨论了正弦位置编码，现代模型也有旋转位置等方案；这些方案不改变本节“位置与访问权限分工不同”的结论。

## 3. 多头怎样并行，又怎样合起来

这节用具体形状证明，多头是多套投影和读取，不是几个分类器投票。

先看独立的微型接口：输入两行，每行4维，设两头，每头输出2维。第一头在两位置输出 `[[1,2],[3,4]]`；第二头输出 `[[10,20],[30,40]]`。并头时沿**特征轴**拼接：

```text
位置0：[1,2] 与 [10,20] → [1,2,10,20]
位置1：[3,4] 与 [30,40] → [3,4,30,40]
```

不是把两行变成四行，也不是取平均 `[5.5,11]`。令输出投影的4×4矩阵为：

```text
W_O = [[1,0,0,0],
       [0,1,0,0],
       [1,0,1,0],
       [0,1,0,1]]
```

按数学中的行向量右乘，位置0得到 `[11,22,10,20]`：第一项是 `1×1+2×0+10×1+20×0=11`，第二项是 `2+20=22`，其余两项是10和20。它混合不同头的通道，但仍只处理当前这一行。

完整模型为4头、总宽32，所以每头8维。Q、K、V通常从 `[B,T,32]` 投影后重排成 `[B,4,T,8]`。每头算出的注意力权重是 `[B,4,T,T]`，聚合后为 `[B,4,T,8]`；转置和拼接回 `[B,T,32]`，再做32到32的输出投影。`32÷4=8` 是接口约束，不是经验偏好；若改成宽30、头4，此实现应拒绝。

“不同头可以学不同关系”是容量描述，不是分工承诺。没有人保证头1专门找主语，头2专门找故障；两个头也可能学相近内容。权重图也不能单独证明某个 token 对最终回答的因果影响。

## 4. 从形状检查到边界实验

这节把纸上接口连到可运行检查，运行位置均为课程根目录。

```bash
python3 labs/attention.py --json
python3 -m llm_course.experiments
```

第一条重算上一章的单头局部例，并不代表跑了完整4头模型；第二条包含完整模型的因果前缀检查。阅读 `llm_course/model.py`，找到位置查表、分头、恢复特征轴和输出投影。每看一处先写下输入输出形状，再核代码。不要用“最后能运行”代替轴检查：沿错误轴 softmax 有时也能输出同形张量，却已经改变了含义。

故障练习：如果去掉因果遮罩而保留位置表，改末尾字符仍可能改变第一行输出；如果只去掉位置表，因果检查仍可能通过。两次实验检验的是不同功能。

## 5. 换数小测

这节用三个新问题检查是否能独立跟踪接口。

1. token 向量 `[2,-1]` 加位置向量 `[-0.5,0.25]` 后是什么？能把位置直接加到 token ID 上吗？
2. 三个头各输出 `[2,5]`、`[0,1]`、`[-1,3]`，拼接结果是什么？若输出宽度为6，共有4头，按本课等宽分头能成立吗？
3. 某模型因果检查通过，是否证明它具有学习式位置表？怎样说明理由？
