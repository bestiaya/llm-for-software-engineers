# 共享数据

这里的数值和任务描述都是课程自编的教学材料。

| 文件 | 用途与来源 |
| --- | --- |
| [counter-task.json](counter-task.json) | 第 04 到 10 章的 16 行数值任务。两条通道最近三次检查的超时次数，各取 0、1、2、3，共 16 种输入；标签是超时达到 2 次的通道数，取 0、1、2。每一行写明了它的用途。第 04 章逐行核对。 |
| [linear-model.json](linear-model.json) | 第 05、06 章使用的九个参数：两项输入、三个分数、六个权重、三个偏置。手工设定，没有经过训练。文件里保留的示例学习率字段现在没有章节使用。 |
| [linear-parameters.f32](linear-parameters.f32) | 与上面 JSON 中相同的九个数，按小端单精度浮点数保存。先一行一行地存 2 行 3 列的权重，再存三个偏置，共 36 字节。第 05 章的实验加载时检查两份参数逐个相等。 |
| [network-training-record.json](network-training-record.json) | 2 个输入、4 个隐藏单元、3 个类别的小网络按声明的设置训练一遍留下的记录：起点、各检查点在训练和验证数据上的损失与正确行数、用验证损失选定的检查点、选定后在留出三行上的逐行结果，以及两个参照。由 `10-training/lab.py --write-record` 生成，默认运行会重新训练并与它核对。第 04 章回放它，第 10 章细读它。 |
| [tiny-lm-training-record.json](tiny-lm-training-record.json) | 七词小语言模型（一层、一个注意力头、77 个参数）按声明的设置训练一遍留下的记录：输入与目标、起点、第一次更新里四个参数的前后值与两种算法的梯度、各检查点的损失、同一段前文在第 0、1000、20000 步的输出、训练得到的全部参数，以及损失的下限和“不看前文”的参照。由 `14-forward/lab.py --write-record` 生成；`--record` 核对它自己对不对得上，加 `--retrain` 把全部步数重新训练一遍。供阶段三使用。 |
| [window-contrast-record.json](window-contrast-record.json) | 窗口对照用的训练记录。三个固定窗口的小模型（1、2、4 个槽，分别有 35、49、77 个参数）不用注意力，用与七词小语言模型相同的种子、学习率和步数各训练一遍：起点、各检查点的损失、训练得到的全部参数、三段前文的输出、能不能把两句话接对，以及只看得见这么多前文时损失最低能到多少。另记有换 20 个起点各训练一遍的结果，并排放着七词小语言模型同样做法的结果。由 `13-attention/lab.py --write-record` 生成；`--record` 核对它自己对不对得上，加 `--retrain` 把全部步数重新训练一遍。供阶段三使用。 |

16 行数据固定分为训练 10 行、验证 3 行、留出 3 行。标签 0、1、2 的行数在训练组是 2、6、2，在验证和留出两组都是 1、1、1。哪一行归哪一组，由数据文件逐行指定，在训练之前就定好。这道题用规则可以直接算出答案；让网络从一部分样本里学，是为了观察训练、选择和检查的过程。留出的 3 行不能说明任何真实场景里的准确率。

第 04 到 09 章的实验都不训练，只做核对、前向计算和一次更新；故意改错的数据和参数只在内存里，再次运行会重新读取这里的原始文件。第 10 章的实验会真的训练，但不写任何文件，除非运行课程维护用的 `--write-record`。

第 01 章使用天气查询的[应用输入](../01-request/inputs/weather-request.json)、[GPT 请求与回答](../01-request/records/chengdu-gpt.json)以及[天气服务快照](../01-request/records/chengdu-forecast.json)。城市与天数可同用户原话核对，展示的逐日预报可同天气响应中的日期、温度和单位核对。
