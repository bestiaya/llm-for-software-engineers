# 22 章课程口径

本课课程号为 `K01`。章号使用课程号加两位连续序号，例如 `K01-02`；课程导读沿用课程号，章内小节以标题和原有锚点定位。Markdown 章标题使用这个章号，与 course.json 的 code 和 number 一致。

本文件给课程维护者使用。学习者从 README 与各章正文进入。

## 读者与路线

主线面向有软件工程基础、没有系统学过机器学习的应用工程师。通过原理、可核对的计算和实验，解释模型怎样运行、能力的边界和工程上的对策。

课程只有一条必修路径，暂定 22 章，分五个阶段，按顺序学完。选读内容在各章里与必修部分分开，不成为后面必修章节的前提。三项成果的深度限定为解释、在给定材料上分析、借助脚手架完成。

## 阶段一的约定版本

第 01 章保留两字段约定（city、days）下的一次历史成功调用，请求与录制保持配套。第 02 章把应用的约定扩成查询、请求澄清、不支持三种结果，默认天数和天数范围由应用决定。第 03 章先固定新约定，再用同一标准评价新旧两版应用。十条天气题只用于演示、开发和回归，不据此估计普遍的可靠性。

## 一贯的说法

模型参数是参与计算的可调数值，训练改变参数，推理使用参数。模型服务是承载模型计算的对外服务。应用负责组装请求、获取资料、调用、检查和业务执行。模型生成的内容、程序检查的结果和业务动作各自记录。

明确假设下的计算、权限和业务状态约束，可以由程序保证部分性质。开放问题的语义正确性需要另行评估。记录保证的性质、前提、来源、执行位置、验证办法与未核实的语义。

给定数字、拟合小例、真实模型任务和模拟执行器分别限定证据范围。手设值与训练结果注明来源。回放历史记录与新调用注明发生方式。模型版本或内部指标无法取得时保留未知。

## 写正文时的技术口径

| 主题 | 口径 |
| --- | --- |
| 事实与参数 | 不说“改不了单条事实”。说“通常缺少按业务记录定位、可靠读改删的接口” |
| 生成方式 | “逐步给出下一个 token 的分布”限定为典型的自回归模型。聊天和工具调用有格式约定，按约定行事的能力是训练出来的 |
| 无依据的回答 | 不写成生成机制的必然结果。分开讨论信息不足、训练目标、能力、表达和验证条件 |
| 可复现 | 分开讨论解码随机性、数值与服务实现、版本和输入变化。不说原则上做不到 |
| 状态与记忆 | 分清本次上下文、服务保存的历史和权威的业务状态 |
| 结构化输出 | 格式保证是有条件的；仍要处理截断、拒答、接口错误和业务语义 |
| 夹带的指令 | 是持续存在的安全问题。模型的抵抗能力和执行权限的约束分开讨论 |
| 费用与耗时 | 与架构、实现和计费规则有关；单价和计算量不是一回事 |
| 限制的写法 | 写清适用对象、成立条件、证据和重新判断的触发条件。不清楚的标“尚不清楚” |
| 模型比较 | 在同一批题上配对比较，看逐题翻转；“直接替换”和“适配后比较”分开 |
| 评测用的题 | 反复查看过的题叫开发题或回归题；最终检查用没参与选择的题 |
| 实验设计 | 现象实验不以模型必然失败为前提；没有波动、正确拒答、没被夹带的指令带偏，都是有效结果 |
| 录制口径 | 已有的 Codex 命令行用量统计不能直接当作模型接口的计费样本；离线回放的耗时不能当作在线服务的延迟样本 |

一般概念的主讲归属见 COURSE_OUTLINE.md。数字和局部流程可在相应章节完整展开，后续主讲的机制在其他章只作导入和回指。

## 文档的形式

课程内容只维护 Markdown，它是唯一的出口：各章的 `lesson.md` 和课程导读 `ABOUT.md`。仓库里不保存由正文生成的网页。

图是各章 `assets/` 目录里的 SVG 文件，由正文引用。

需要交互演示的章，在该章目录里放一个独立的网页，例如 `demo.html`，由正文指过去。约定如下：

- 单个文件，只用普通的 HTML、样式和脚本，不需要构建，不依赖外部库，下载仓库后双击就能打开。本地打开的网页读不了旁边的数据文件，数字直接写在页面里。
- 演示里的数字由该章的 Python 实验导出，并有测试核对两边一致。
- 正文里保留静态的图、解释和命令。演示是增强，不是理解正文的唯一途径。
- 在 GitHub 上点 `.html` 的链接看到的是源代码，所以正文里写明“下载仓库后用浏览器打开”。
