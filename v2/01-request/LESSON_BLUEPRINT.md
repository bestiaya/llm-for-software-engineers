# 第01章教学蓝图

面向会编程、尚未系统学过机器学习的软件工程师。读完能画出一次天气查询的数据流，说清模型服务、天气服务和应用各自收到什么、交回什么，并指出模型交回的是一段要由应用解析和核对的文本。

## 阅读顺序

1. 从“帮我看看成都未来三天的天气”开始，先不碰终端，走完四步：应用把指令和原话交给模型，模型交回一段文本，应用解析后查询天气服务，应用展示逐日预报。用一张三方分工表收住。
2. 回放随课保存的真实请求和响应。读者在终端输出里找到模型交回的原文、解析出的参数，再到天气快照里找到温度的出处。写清默认是回放，不联网，不重新调用模型。
3. 说明应用凭什么相信这段文本：形式能不能读，值是不是用户要的，数据是不是对应这次查询。用“两天”和“那里明天”两句引出下一章。
4. 用一张技术关系图交代模型、大语言模型、Transformer、参数、训练和推理之间的关系，只建立整体认识，不展开。
5. 四道小测检查读者能否不看终端讲清这条链路。
6. 排错放在后面，选做。最后说明直接使用 ChatGPT 桌面端时，同一句话由谁来接模型和外部信息。

## 核对依据

正文里的城市、天数、日期、单位和温度，以 `records/chengdu-gpt.json` 和 `records/chengdu-forecast.json` 为准。采集方式、模型标识能知道到什么程度，见 `records/README.md`。

本章保留两字段的约定和与它配套的历史录制。三种结果的新约定从第 02 章起使用，不在本章提前引入。

回放展示的是采集时的预报，不当作读者运行当天的实时预报，也不当作实况。
