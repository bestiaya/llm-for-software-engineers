# K01-08 从分数到概率和损失

上一章的网络给每一行输入算出三个分数，取最大的作为答案。要让程序自己去调参数，先得有一把尺子，能量出“这组参数现在做得怎样”。

最容易想到的尺子是选对了几行。这一章先说它为什么不够用，再分两步做一把更细的：**先把三个分数变成三个概率，再用正确类别的概率算出一个数，叫损失。**

这一章会用到指数和自然对数。不需要事先学过，用到的地方都先给数值表，对着表能算就行。公式放在最后，可以跳过。

<a id="why"></a>

## 选对几行，这把尺子太粗

**这节在干嘛**　说清“选对的行数”缺什么，新尺子要补上什么。

**它分不出同样选对的两个结果。** 上一章的网络对 a=0、b=2 算出的分数是 −1、0、−1，选了类别 1，对了。假如另一组参数算出的是 −3、0、−3，也选类别 1，也对了。两者在“选对几行”上完全一样。可第二组把正确的类别和另外两个拉得更开，直觉上应当算更好。

**它对小改动没有反应。** 把某个参数改动一点点，三个分数只变一点点，最大的那个多半还是原来那个，选对的行数纹丝不动。这样就无从知道这一点改动是让模型变好了还是变坏了，调参数也就没有方向。

所以新尺子要满足两条：同样选对也能分出高下；参数稍有变化，它也跟着稍有变化。

<a id="softmax"></a>

## 第一步：把分数变成概率

**这节在干嘛**　把三个可正可负、大小随意的分数，换算成三个加起来等于 1 的正数。

分数已经够用来选类别了。为了做后面的损失，再把它们换算成“三个类别各占多少份额”：每一份都大于 0，三份加起来是 1，分数越高份额越大。

换算分三步：**取指数，求和，各自除以总和。**

先认识“取指数”。有一个固定的数 e，约等于 2.718。一个数 x 的指数写作 e^x：

| x | −2 | −1 | 0 | 1 | 2 |
| --- | ---: | ---: | ---: | ---: | ---: |
| e^x | 0.135 | 0.368 | 1 | 2.718 | 7.389 |

用得到的性质只有三条：结果总是正数；x 越大结果越大；x 每增加 1，结果乘 2.718。

为了好算，先挑三个特别的分数，让它们取指数以后正好是 1、2、3。这三个分数约等于 0、0.693、1.099。

| | 类别 0 | 类别 1 | 类别 2 |
| --- | ---: | ---: | ---: |
| 分数 | 0 | 0.693 | 1.099 |
| ① 取指数 | 1 | 2 | 3 |
| ② 求和 | | 6 | |
| ③ 各自除以总和 | 1/6 ≈ 0.167 | 2/6 ≈ 0.333 | 3/6 = 0.5 |

三个结果都是正数，加起来是 1，分数最高的类别 2 拿到最大的一份。按[课程导读的实验准备](../ABOUT.md#lab-setup)进入仓库根目录，让程序算一遍：

```bash
python3 v2/08-loss/lab.py
```

再算上一章那一行真实的分数。a=0、b=2 的三个分数是 −1、0、−1：

| | 类别 0 | 类别 1 | 类别 2 |
| --- | ---: | ---: | ---: |
| 分数 | −1 | 0 | −1 |
| ① 取指数 | 0.368 | 1 | 0.368 |
| ② 求和 | | 1.736 | |
| ③ 各自除以总和 | 0.212 | 0.576 | 0.212 |

```bash
python3 v2/08-loss/lab.py --row 0 2
```

这三步合起来叫 **softmax**，算出的三个数叫模型给三个类别的**概率**。它是模型按当前参数分给各个类别的份额，不自动等于“这样回答有多大比例是对的”；算完损失以后再回来细看这一点。写成代码：

```python
import math


def softmax(scores):
    powers = [math.exp(score) for score in scores]     # ① 取指数
    total = sum(powers)                                 # ② 求和
    return [power / total for power in powers]          # ③ 各自除以总和
```

课程代码里的版本多了一步：先把每个分数都减去其中最大的那个，再取指数。这是为了分数很大时不至于算溢出，结果完全一样。本章的实验算概率用的就是这个版本；分数很大时，它会把减过以后的数显示出来。

softmax 有两个性质，可以自己用 `--scores` 试出来：

- **只有分数之间的差距起作用。** 三个分数都加上同一个数，概率不变。0、1、0 和 −1、0、−1 算出的概率一模一样；都加上 1001，变成 1000、1001、1000，也还是一样。
- **差距越大，份额越悬殊。** 把 −1、0、−1 都乘 3，变成 −3、0、−3，类别 1 的概率从 0.576 升到 0.909。

```bash
python3 v2/08-loss/lab.py --scores=0,1,0
python3 v2/08-loss/lab.py --scores=1000,1001,1000
python3 v2/08-loss/lab.py --scores=-3,0,-3
```

<a id="loss"></a>

## 第二步：用正确类别的概率算损失

**这节在干嘛**　把“这一行做得怎样”压成一个数。

每一行都有标签。只看模型给**正确类别**的那一份概率，记作 p。p 越接近 1 越好。我们想要一个数来表示“差多少”：p 等于 1 时是 0；p 越小它越大；p 接近 0 时它非常大。

符合这些要求的一个现成算法是 **−ln(p)**。ln 叫自然对数，是取指数的反操作：e^x 等于某个数，ln 这个数就得回 x。例如 e^0 = 1，所以 ln(1) = 0；e^(−1) = 0.368，所以 ln(0.368) = −1。0 到 1 之间的数取 ln 都是负的，前面加个负号就成了正数。

对着表看它的脾气：

| 正确类别的概率 p | 0.99 | 0.75 | 0.5 | 0.25 | 0.1 | 0.01 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| −ln(p) | 0.010 | 0.288 | 0.693 | 1.386 | 2.303 | 4.605 |

p 接近 1 时它接近 0。p 从 0.5 掉到 0.25，它涨 0.69；p 从 0.1 掉到 0.01，它涨了 2.3。**把很小的概率分给正确答案，罚得特别重。**

这个数叫这一行的**损失**。这种算法的全名是负对数损失，也常叫交叉熵损失。损失越小越好。

用它回答本章开头的比较。正确类别都是 1：

| 三个分数 | 正确类别的概率 | 损失 |
| --- | ---: | ---: |
| −1、0、−1 | 0.576 | 0.551 |
| −3、0、−3 | 0.909 | 0.095 |

同样是选对，第二组的损失小得多。新尺子把它们分开了。

还有一个值得记住的参照：三个分数全相等时，三个概率各是三分之一，无论标签是哪一类，损失都是 −ln(1/3) = 1.099。这相当于“什么都不知道，三类平分”。一个模型的损失如果比 1.099 还高，说明它比平分还差。第 04 章概览里，调整之前的验证损失是 1.3038，就是这种情况。

<a id="mean"></a>

## 很多行：取平均

**这节在干嘛**　从一行的损失得到一组数据的损失。

一组数据有很多行，每行各有一个损失。把它们加起来除以行数，就是这组数据上的**平均损失**。

先做一道小的。三行数据，模型给正确类别的概率分别是 0.25、0.5、0.75。查上面的表：

    (1.386 + 0.693 + 0.288) ÷ 3 = 0.789

```bash
python3 v2/08-loss/lab.py --losses=0.25,0.5,0.75
```

再看上一章手设的网络在全部 16 行上的情况：

```bash
python3 v2/08-loss/lab.py --all
```

16 行全部选对。每一行的最后两列是正确类别的概率和损失：8 行是 0.721 和 0.327，8 行是 0.576 和 0.551。平均损失是 0.4390。

写成代码：

```python
def mean_loss(probabilities, labels):
    """probabilities 每行三个概率，labels 是每行的正确类别。"""
    losses = [-math.log(row[label]) for row, label in zip(probabilities, labels)]
    return sum(losses) / len(losses)
```

第 04 章概览里的“验证损失”，就是在验证的 3 行上算的平均损失。

到这里，新尺子做好了：**一组参数，一组带标签的数据，算出一个平均损失。** 它满足开头的两条要求。同样选对也分得出高下；不改变最终类别的小改动，它通常也能反映出来。也有例外：有的参数动一点，损失并不变，下一章会遇到。

<a id="meaning"></a>

## 这个“概率”是什么，不是什么

**这节在干嘛**　损失做好了，回到第一步算出的概率，给它一个准确的解释，免得把它读过了头。

softmax 算出的概率，是**模型按当前参数给每个类别分配的份额**。它加起来等于 1，是算法保证的，不是因为模型对现实有什么把握。

它**不自动等于**“这样回答时有多大比例是对的”。用实验看这件事。上一节看过，手设的网络在 16 行上全对，给正确类别的概率只有两种：0.721 和 0.576。现在把输出层的权重和偏置都乘 3，三个分数因此都乘 3：

```bash
python3 v2/08-loss/lab.py --all --scale 3
```

| | 选对的行数 | 给正确类别的概率 | 平均损失 |
| --- | --- | --- | ---: |
| 原来的参数 | 16/16 | 0.721 或 0.576 | 0.4390 |
| 输出层乘 3 | 16/16 | 0.953 或 0.909 | 0.0718 |

两组参数在每一行上选的类别完全相同，都是 16 行全对。可在同一行上，一组给正确类别 0.576，另一组给 0.909。**选得对不对是一样的，概率却不一样：分类的正确率，不能从 softmax 给出的数直接读出来。**

所以：

- 模型给的概率反映的是分数之间的差距，差距又取决于参数的大小。
- 这个数可不可信，要拿数据去检验：在要用的那类数据上，把模型给出相近概率的预测放在一起，看其中实际对了多少。两者相符的程度叫**校准**。校准得好的模型，概率可以当作正确的比例来读；这里的例子只说明两者不会自动相等。

这一点对后面很重要。大语言模型生成文字时，典型的做法是一小段一小段往后接；这样的小段叫 token，第 11 章细讲。每接一段之前，模型给出的也是这样一组概率，只是候选从 3 个类别变成了几万个 token。**某个 token 的概率很高，不等于整段回答在事实上是对的。**

## 损失和选对的行数，说法不一样的时候

**这节在干嘛**　两把尺子量的不是同一件事。看它们什么时候给出相反的排名。

下面是人工构造的两个模型，在同样三行数据上给出的概率。三行的正确类别都是 0。

```bash
python3 v2/08-loss/lab.py --disagree
```

| | 三行各自给三个类别的概率 | 选对的行数 | 平均损失 |
| --- | --- | --- | ---: |
| 模型甲 | 三行都是 0.4、0.3、0.3 | 3/3 | 0.916 |
| 模型乙 | 两行是 0.9、0.05、0.05，一行是 0.3、0.6、0.1 | 2/3 | 0.472 |

按选对的行数，甲好；按平均损失，乙好。

- 甲每一行都选对了，但每次都只比别的类别高一点点。
- 乙有两行选得又对又有把握，第三行选错了，给正确类别留了 0.3。

哪个更好，取决于你要用它做什么。选对的行数只看最大的那个类别对不对；损失还看分给正确答案的份额有多大，并且对“有把握地答错”罚得重。

罚得有多重，可以在手设的网络上看。把 h2 的偏置从 −2 改成 −3，网络会在两行上选错：

```bash
python3 v2/08-loss/lab.py --all --set "b1[h2]=-3"
python3 v2/08-loss/lab.py --all --set "b1[h2]=-3" --scale 3
```

选错的那两行，损失是 1.33。再把输出层乘 3，它们的损失涨到 3.05：分数差距拉大以后，模型在这两行上错得更“有把握”了，给正确类别只留下 0.047。

两把尺子各有用处，后面都会用：

- **训练用损失。** 它对参数的小改动有反应，能指出方向。下一章就靠它。
- **向人报告时，选对的行数更直观。** 但要像第 03 章那样，同时看逐行的结果。
- **判断学得怎样时，两个都看。** 第 10 章会遇到选对的行数不变、损失却在变坏的情况。

## 公式（可以跳过）

把前面的内容写成记号。三个分数记作 z₀、z₁、z₂，正确类别记作 y：

    概率　　p_k = e^(z_k) ÷ (e^(z₀) + e^(z₁) + e^(z₂))
    一行的损失 = −ln(p_y)
    平均损失 = 各行损失之和 ÷ 行数

## 尺子有了，参数往哪边改

到这里，你能把一行的三个分数变成三个概率，用正确类别的概率算出损失，再对一组数据取平均；也知道模型给的概率不自动等于现实里的正确率。

现在可以把“让模型变好”说成一件明确的事：**调整参数，让训练数据上的平均损失变小。** 可网络有 27 个参数，每个该往大调还是往小调，调多少？[第 09 章](../09-update/lesson.md)回答这个问题。
