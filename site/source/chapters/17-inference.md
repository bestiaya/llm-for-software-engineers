# 17｜推理与KV cache：省掉重复计算，保留同一问题

本章回答：已经算过的前缀，下一步为什么还要算？怎样复用而不改变logits？先读[完整decoder](12-decoder.md)和[逐步生成](13-next-token.md)。缓存是计算复用，不是让模型多记住训练外的知识。

## 1. 哪些计算可以保留

这节追踪从3个token到4个token的增量，确定缓存真正存了什么。

提示为ABC时，各层已经得到A、B、C各位置的键K和值V。生成D后，D的查询Q需要读取A/B/C/D的键值。因为因果遮罩下A/B/C的表示不依赖未来D，在固定模型与位置条件下，旧K/V不必重算。只为D计算新Q/K/V，再把新K/V接到缓存尾部。

| 第4个位置要做的事 | 无缓存 | 有缓存 |
|---|---|---|
| 计算旧A/B/C各层表示 | 再算 | 复用缓存 |
| 计算新D各层Q/K/V | 要算 | 仍要算 |
| 新D读取历史键值 | 要算 | 仍要算 |
| 新D的FFN和词表输出 | 要算 | 仍要算 |

为什么不只缓存最后一层？每一层的新token都要读**该层**旧token的K/V；上一层与下一层的投影参数和表示不同，不能拿一层缓存冒充所有层。

## 2. 手算缓存为何可以等价

这节用一维局部例核对“缓存”和“重算”用了完全相同的数。

设旧两个键为 `[1,0]`，对应值 `[2,4]`；新token的查询是1、新键为1、新值为6。这里每头键宽1，所以缩放除以sqrt(1)仍为1。新行的分数是 `[1,0,1]`，指数为 `[e,1,e]`，e约2.71828，总和约6.43656。权重约 `[0.422319,0.155362,0.422319]`，加权值为：

```text
0.422319×2 + 0.155362×4 + 0.422319×6
≈0.844638+0.621448+2.533914=4
```

重算路径重新生成三个键值，再做这一步；缓存路径复用前两个键值，只算第三个。只要两路给出的键值确实相同，加权结果就相同。这个局部例没证明所有代码正确；它指出等价的前提是“数没变”，而不是“都叫缓存”。

完整模型的浮点加法顺序可能不同，所以按容差比较logits，而不要求每个二进制位完全相同。更不能只比较最终argmax：`[0.51,0.49]` 与 `[0.9,0.1]` 会选同一token，分布却相差很大。

## 3. 等价需要哪些前提

这节列出可执行的等价条件，避免把一个局部测试推广到任意模型。

同一权重、同一token前缀、同一位置编号、同一因果访问规则、相同精度与兼容计算路径；模型处于eval模式，不启用随机dropout，比较时不更新参数。`eval()` 和“不算梯度”不是同一开关：前者影响训练态行为，后者关闭梯度记录。此实现dropout为0，仍明确采用eval/no_grad来表达推理用途。

本课接口 `Decoder(config).forward(ids, cache=None)` 返回 `(logits, cache)`；第一次可输入整段前缀，后续只传新token并带上旧cache。缓存是每层 `(K,V)` 的集合，位置从缓存长度继续，不能每次增量都重置到0。若把整个ABC又传给保存ABC的缓存，实际变成重复拼接，不是“更保险的输入”。

还要防止多token增量时的遮罩错误。假设旧长度3，一次追加D/E：D允许读旧3项加自己，共4项；E允许读旧3项加D/E，共5项。若套一个从0开始的2×5普通下三角而不加历史偏移，D可能只能读第一项，逻辑已经变了。

## 4. 上下文溢出为什么不能悄悄裁剪

这节处理缓存寿命，知道正确停止比隐藏状态错位更可靠。

本模型学习式绝对位置只有0到63。缓存已有64位置时，再追加一个token会报 `ValueError`；生成器会在剩余上下文预算耗尽时停止，不自动滑窗。它不是无限长对话。

如果删掉第一个缓存token却保持旧K/V，其余向量仍是旧位置及旧前缀下计算的结果。把剩余位置重新编号0起算也不够：旧K/V包含旧位置表示，深层表示还读过被删前文。不能认为“少一个元素”就完成了语义重置。

可明确选择的另一种策略是：丢弃全部旧缓存，取选定短前缀，从位置0完整重算。这得到的是**新短上下文任务**，可与同一短前缀的无缓存结果比较，却不等价于原完整历史。新会话、修改旧消息、切换模型权重也都应重建缓存。缓存命中错误会稳定输出错误结果，不一定触发形状异常。

## 5. 内存预算与现代优化的边界

这节算缓存字节数，理解缓存不是免费加速，也不是所有推理都用同一方案。

对标准多头注意力，设批大小1、2层、长度64、4头、每头8维，float32每数4字节。K和V各一份：

```text
缓存数值个数 = 2(K和V) × 2层 × 1批 × 64位置 × 4头 × 8维 = 8192
字节数 = 8192 × 4 = 32768字节 = 32 KiB
```

KiB是1024字节；这只算K/V数组，不包括权重、临时分数、激活、Python对象与分配器开销。长度翻倍，其他条件固定，K/V字节数翻倍。新token仍要读更长历史，所以有缓存不表示后面的每一步耗时恒定。

选修阅读：MQA/GQA让多个查询头共享键值头，减少缓存宽度；量化缓存改变每数存储与误差；分页管理改内存分配；FlashAttention一类方法优化注意力计算与数据搬运。它们不是同一种机制，也不意味着都已实现于本课。不能把上面的32 KiB算式原样套到所有模型；先查层数、KV头数、维度、精度和额外状态。

## 6. 跑等价检查，保留误差

这节运行真实实现，并把通过范围说完整。

```bash
python3 -m llm_course.experiments
python3 -m unittest discover -s tests -v
```

实验用固定随机权重与固定前缀，在eval/no_grad条件下比较完整与逐token缓存logits，同时测试未来替换不改变过去。输出的 `cache_max_error` 是最大绝对误差；先看数值与容差，再看是否通过。随课固定小实验的一次实跑中，因果前缀最大误差为0，完整/缓存logits最大绝对误差约 `3.58×10⁻⁷`，低于脚本的 `2×10⁻⁶` 容差。这些数对应脚本中的宽16、2层、随机初始化小模型，而不是训练报告中的宽32模型。它验证计算复用，不需要训练出语言能力；也不能由一个短前缀测试证明任意设备、精度、长度都等价。
