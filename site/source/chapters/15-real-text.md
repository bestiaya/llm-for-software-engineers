# 15｜自然语言小实验：从会跑到知道没学会什么

本章将同一个小decoder放到真实英文文本上，学习如何记录来源、切分、耗时、损失与失败。先完成[toy训练](14-toy-training.md)。这一步增加了语言复杂度，但没有把模型升级成聊天助手，也不检验中文能力。

## 1. 真实文本为什么改变问题

这节说明真实语料增加了哪些困难，避免把“换一个文件”理解为相同难度的任务。

有限语法的句子结构受控；自然文本包含长距离依赖、稀有字符、不同叙述语气和大量不重复表达。64字符的前文可能连一段完整句子都装不下。即使训练损失下降，模型也可能只学会字母、空格和短片段搭配。

课程随附 Lewis Carroll 的英文原作 *Alice's Adventures in Wonderland*。准备后的训练输入在 `data/real.txt`；来源、原始与处理后SHA-256、提取方式写在 `data/real-provenance.json`，未修改下载源和许可文本留在 `data/sources/`。SHA-256是内容指纹：一个字节变了，核对值通常就变；它证明两份内容是否一致，不证明文学质量或模型效果。

不要凭文件名断言权限，也不要把代码许可证自动覆盖到语料上。再分发依据与使用地区说明以[数据说明](../data/README.md)和随附许可为准。课程不要求联网抓取新的网页，来源记录与正文同时保留。

## 2. 先按连续文本分区，再各自切窗口

这节跟踪一次小切分，分清原始字符、词表ID与训练窗口。

实现先按原始字符顺序以80%/10%/10%划分训练、验证、测试，再只用训练区建立字符词表。假设独立教学文本恰有1000字符，那么前800训练，接着100验证，最后100测试；真实长度和取整结果看当次报告。窗口不能从训练区尾巴伸进验证区开头。

![连续文本分为80百分比训练及各10百分比验证和测试](../assets/diagrams/15-real-text-1.svg)

训练区没出现过的字符在其他分区映射到UNK。假设训练字符集是 `{a,b,空格}`，验证文本是 `ab!`，它会变成 `[id(a),id(b),UNK]`，不能为了降低未知率回头把 `!` 加到训练词表。报告应该让读者看见未知字符的数量或局限；UNK损失好看也不表示模型区分了原来的所有稀有字符。

这里连续切分减少跨边界的窗口泄漏，却不保证不同区统计独立。同一本书可能重复人名、句式和完整短语；叙述顺序也会造成前后分布不同。不能把这个测试集称作“全世界英文的代表”。

## 3. 运行与保存一次真实记录

这节执行同一模型的自然语言训练，结果由文件承担，不由教材预先猜测。

从课程根目录运行：

```bash
python3 -m llm_course.train --dataset real --steps 300 --out outputs/real
```

默认仍是宽32、4头、2层、上下文64、字符级预测，300次更新。产物为 `report.json`、`report.md`、`checkpoint.pt` 和 `sample.txt`。先读随课的[实际自然文本运行记录](../reports/real.md)，再对照自己输出。报告里的种子、版本、CPU与耗时属于那次运行；不能把某台机器的秒数写成所有电脑的性能保证。

| 阅读顺序 | 要问的问题 | 不足以推出的结论 |
|---|---|---|
| 来源和切分 | 输入是哪版文本、目标来自哪区 | 有来源不等于分布代表所有语言 |
| 配置和预算 | 实际几层、几步、上下文多长 | 参数更多不保证分数更好 |
| 基线和test CE | 同目标上谁损失更低 | CE低不等于回答事实正确 |
| 样本和停止原因 | 真输出了什么、为什么停 | 单句流畅不等于总体可靠 |
| 失败与限制 | 有哪些反复出现的问题 | 没列出的错误不等于不存在 |

随课实跑采用种子42，词表73项、32,192个参数，选中第300步。原字符分区为训练115,212、验证14,402、测试14,402；测试目标14,402个，验证有4个未知字符。具体结果如下：

| 模型 | 同一测试目标上的每目标CE |
|---|---:|
| decoder | 2.450565 |
| unigram | 3.172494 |
| bigram | 2.442503 |

decoder比bigram略高约 `2.450565-2.442503=0.008062`，**这次没有胜过bigram**；它比unigram低，支持其学到超出全局字符频率的一些规律，但不能证明理解。单次结果也不确定差距在换种子后是否保持。该次总耗时2.333秒，是记录环境下的实测，不是所有CPU的承诺。

报告中的真实贪心样本原样为：

**输入提示（不是模型生成）**

```text
CHA
```

**模型新增内容**

```text
l the the the the the the t the the the the the the the the t
```

停止原因是context_limit，未生成自然结束。可见重复“the”和不完整片段。贪心、短上下文、有限更新与小模型都是候选影响因素；本次没有逐项对照，不能指定其中一个是已确认原因。

还可以核对两个具体条件。评价按不重叠的64字符窗口重新开始位置和上下文；每个满窗口的第一个目标只有1字符前文，最后一个目标有64字符，平均是(1+64)/2=32.5字符，不能把“context=64”读成每个目标都看了64字符。报告history中的验证CE在本次300步内仍持续下降，提示优化预算可能未充分。可另存新目录、只按训练/验证比较更多步数；它是待检验假设，不是已经确认的失败原因。

别因为看见几个真实单词就忽略乱码与循环。报告展示的样本应保留原样，不能手工补标点、改语法，再把修订后文本署为模型输出。

## 4. 损失怎样帮助理解，怎样误导

这节用小数字解释困惑度，并说明为什么它不能跨分词方式随意比较。

假设三个真实目标的概率是 `0.5、0.25、0.5`。平均CE为 `(0.693147+1.386294+0.693147)/3≈0.924196`。把自然常数e取这个指数，得到困惑度约 `exp(0.924196)=2.519842`。`exp`读“指数函数”，是自然对数的逆运算；困惑度常写PPL。

它把平均对数损失转换到另一个尺度，越低仍表示同一批目标上分布更贴近实际目标。它不是“模型大约只懂2.52个词”，也不是“每次必定有2.52个等可能候选”。均匀三选一时CE为ln3，PPL才正好为3；本例三次分布并不相同。

字符级和子词级模型的一个token长度不同，所以每token CE/PPL不能直接判断谁语言更强。即使都字符级，测试文本、UNK策略和EOS口径不同，也不能只摘两个数排名。本课程只比较当前相同目标集合的模型。

## 5. 失败报告比精选句子更有用

这节把失败分成可定位的层次，为下一章的规模和后训练建立问题。

若输出重复几个字符，先问它们是否在训练中高频、是否总用贪心、上下文是否过短；若文字像原书片段，检查是否复现训练片段，不能把记忆当成新知识推理；若测试CE不如bigram，保留结果，再检查优化预算和任务结构，不为迎合预期而换口径。

一次有价值的记录至少包含：固定提示、原始生成、停止原因、一条成功现象、一条明确失败、候选解释及区分解释的下一项实验。例如“重复可能来自贪心”只是解释候选；还没有改变策略比较，就不能断言原因已确认。

可以改变种子或训练步数做扩展，但每次单独存目录，只用训练/验证做选择。本课程制作与实现检查已使用过这份固定测试区，它不是新的盲测。重新运行命令不会使这段历史消失。

## 6. 换数小测

这节检查是否能给自然语料实验下恰当结论。

1. 2000字符按80/10/10连续分区，各区多少？先切成重叠窗口再随机分有什么风险？
2. 同一目标集上模型CE为ln4，困惑度多少？能说“有四个词等概率”吗？
3. 十条样本中挑出最好一条展示，且没有保存其他九条，读者能判断什么？应该怎样补记录？
