# 14｜CPU训练：让每一项结果都有来处

本章跑一个完整的微型decoder实验。目标是核实参数确实更新、数据分工正确、选出的模型能按规定评估，而不是把几句生成样本当成“已经理解语言”。先读[下一token训练](13-next-token.md)，并按课程入口安装训练依赖。这里不用API密钥，也不要求GPU。

## 1. 为什么先用有限语法

这节先收窄模型要学的对象，避免训练出一点规律就宣称得到通用助手。

课程的toy数据是原创的有限语法文本组。它保留可检查的组合规律，规模小，适合在CPU上发现标签、因果遮罩、梯度和评估口径错误。真实世界的措辞变化、事实知识和用户意图远比这些组复杂。模型生成符合模板，只支持它在该数据设定下学到某些模式。

想象两个教学组：“服务甲超时，建议重试。”和“服务乙正常，无需重试。”若先把两句切成大量重叠窗口，再随机划分窗口，几乎相同的片段可能同时进入训练与测试。测试分数就可能主要反映见过的字符串。这里先按**完整唯一文本组**划分，然后各区内部建窗口，不跨组拼接。这两句仅帮助理解切分，实际内容与数量看数据文件和运行报告。

组不重叠不等于世界独立：各区可能共享同一套语法。它检验的是这套生成分布内的组合，不是跨领域泛化。

## 2. 冻结一次实验配置

这节把运行预算与模型规模写清，保证后来能知道自己比较的是什么。

默认实现为字符级词表，训练集字符排序后编号；UNK为0、EOS为1，没有PAD。以下是默认设置，不是所有Transformer都必须采用的设置：

| 项目 | 本次默认 | 对读者意味着什么 |
|---|---|---|
| 特征宽 / 注意力头 | 32 / 4 | 每头8维 |
| decoder块 / FFN | 2 / 128维GELU | 与前章完整路线一致 |
| 位置 / 上下文 | 学习式绝对位置 / 64 | 不能直接预测第65位置 |
| 归一化 / dropout | Pre-LN加最终LN / 0 | 本实现没有随机丢弃 |
| 批大小 / 学习率 | 16 / 0.003 | 一步看多个训练窗口 |
| toy步数 | 200 | 是200次优化器更新，不是200轮遍历 |
| 计算 | CPU单线程、固定随机种子 | 仍应记录硬件与软件版本 |

训练窗口随机抽取，因此 `step` 不是 `epoch`。`epoch`通常指把训练数据完整走一轮；这里200步不能换算成“每条数据刚好看了多少次”。同一窗口可能重复抽到，某些窗口可能没抽到。

## 3. 跑通最小完整链路

这节执行训练、读产物，先确认完整过程，再考虑增大预算。

从课程根目录运行：

```bash
python3 -m llm_course.train --dataset toy --steps 200 --out outputs/toy
```

产物职责如下：

| 文件 | 应检查的内容 |
|---|---|
| `outputs/toy/report.json` | 实际配置、种子、划分计数、各模型损失、耗时、样本及限制 |
| `outputs/toy/report.md` | 可阅读的实验摘要 |
| `outputs/toy/checkpoint.pt` | 配置、词表和所选模型权重 |
| `outputs/toy/sample.txt` | 真实生成文本及相关记录 |

课程随附的[一次toy运行记录](../reports/toy.md)与自己重跑的输出是两次记录，不能混成一次。若代码、种子或依赖不同，差异先写出来；不靠编辑报告把数值“对齐”。检查点存的是配置与state_dict，加载使用受限的权重读取方式，不需要反序列化一个任意Python模型对象。

随课真实运行使用种子42，共28,288个参数；训练/验证/测试分别201/25/26个文本组，测试有962个目标。所选第200步的decoder test CE为0.174156，unigram为2.316875，bigram为0.191738；三者均在这962个目标上计算。decoder在此单次切分上比bigram低约 `0.191738-0.174156=0.017582`，尚不能由一个种子证明稳定优势。该次训练报告总耗时1.100秒，仅代表报告所记环境。

真实贪心样本是：

**输入提示（不是模型生成）**

```text
服务超
```

**模型新增内容**

```text
时，重试。服务正常。服务正常。服务正常。服务正常。服务正常。服务超时，重试。<EOS>
```

停止原因是eos。它含有重复的“服务正常”，即使符合有限语法，也不能推断模型会根据真实故障作建议。训练使用AdamW，weight decay为0.01、梯度范数裁剪上限1.0：若整组梯度的欧氏长度大于1，就统一缩小到1，避免单次更新被过大梯度主导；并不保证训练稳定。这些设置和完整轨迹以报告为准。

训练每25步及最后一步在validation上计算损失，选validation CE最低的权重；选定后才算test。示意：三个候选步的验证损失为 `1.4、1.1、1.2`，应选第二个；即使第三个训练损失更低，也不能据此覆盖选择。这里三个数是选择规则示例，不是实测曲线。

## 4. 怎样公平比较计数模型

这节用同一批目标算分，学会判断“胜过基线”到底比较了什么。实际toy词表有12项，包含UNK和EOS；第03章手算的3项词表是独立小例，平滑分母必须使用当前实际词表大小。

代码同时评估unigram和bigram：前者不看上文、只根据训练集目标频率；后者看上一个token，计数方法见[计数预测](03-counting.md)。它们与decoder使用同一批窗口、同一组目标。若一个模型多算EOS、另一个少算，平均数再漂亮也不是公平比较。

沿用独立手算：两个窗口分别3目标与1目标，decoder损失总和为 `2.1、1.2`，平均是 `3.3/4=0.825`；bigram对应总和 `2.4、0.6`，平均为 `3/4=0.75`。本例bigram更低。不能因为decoder名称更新，就把这种结果判成实验失败；它可能说明短规则足以解释当前数据，或decoder预算/参数选择不合适。

观察指标的顺序建议是：先数分母，再查划分与训练过程，最后解释高低。如果训练和验证都很差，可能优化未充分、配置不适合，或任务本身难；训练低验证高，要检查过拟合、分布差异与数据泄漏；测试不如验证并不自动说明代码错了。单个切分上的小差距也不提供稳定优势的证据。

## 5. 用失败样本检验理解

这节要求保留不成功输出，防止只展示最顺眼的一句。

至少记录固定提示、完整生成样本、停止原因。标出重复循环、未见字符的UNK、格式不完整和提前EOS。若提示已占64位置，新增预算可能为0；这不是语言失败，而是调用条件耗尽。贪心重复也不直接证明模型完全没有学到规律，要回到概率和生成策略检查。

```bash
python3 -m unittest discover -s tests -v
python3 -m llm_course.experiments
```

这些命令用于查实现约束，不能把测试通过写成语言能力通过。想改学习率或步数时，先保留本次输出到另一个目录，说明只根据训练/验证作新选择。若已经查看测试结果再调整，下一次同一测试集是复用过的测试，不能称完全未触碰的验收。
